## 1. 為什麼用遊戲畫面

表格很難一眼看出「錢在哪、卡在誰手上、在等誰」。把金流畫成一個小鎮，每個問題都有一眼看得到的答案：

- **錢在哪**：主堡倉庫裡堆了幾箱。
- **卡在誰手上**：誰的背包鼓鼓的、誰頭上冒煙。
- **在等誰**：門口那台推車上面的 ❗。

參考了兩款遊戲的**手法**，沒有用它們的角色、圖像或 Logo。角色一律用 Googoocard 自己的奇異鳥。

- **療癒經營遊戲**（使用者提供的截圖）：
  - 鼠尾草綠的地面、奶油色建築、粉色格紋地墊
  - 白色圓角的資源膠囊（HUD）
  - 下方一排圓形按鈕
  - 物件頭上的沙漏和進度條
- **The Colonists**：
  - 物流看得見：貨物堆在倉庫，在路上的東西真的在路上走
  - 路口有路標
  - 角色不開心時冒出驚嘆號

## 3. 視覺規格

### 3.1 視角與畫法

- **2:1 等角**：一格寬 64px、高 32px。投影是 `x = OX + (gx − gy) × 32`，`y = OY + (gx + gy) × 16 − z`。高度 z 用 px。
- **畫的順序**：依 `gx + gy` 從後往前畫；同一疊箱子先畫下層。
- **不描邊**：立體物件的三個面分三個色階，頂面最亮、左前面居中、右前面最暗（光從左上來）。
- **影子**：地上一個柔和的橢圓，`#55632E`，透明度 16%。
- **地面上的平面東西**（路、河、地墊、麥田）放進同一個等角變形群組，用格子座標畫。花紋也會跟著斜，看起來是鋪在地上。

### 3.3 字型

- **數字和英文**：`Fredoka`，600 或 700。圓圓的，可愛的感覺主要來自這裡。
- **中文**：`Noto Sans TC`。
- 寫法：`font-family: Fredoka, 'Noto Sans TC', sans-serif`。Fredoka 沒有中文字，中文會自動落到 Noto。

### 3.4 角色：奇異鳥

- 身體 `#BF9064`，下半部陰影 `#A97C52`，嘴 `#F1D39C`，腳 `#E39B4A`，臉頰 `#F4A79E`。
- **圍巾顏色＝這個人**：丁丁 `#4BB38B`、老師 B `#7FA8E0`、老闆 `#E58B7A`。正式版改用成員或 `Teacher.color` 的色票。
- **配件＝身分或狀態**：
  - 背包：代收人
  - 皇冠：營收負責人
  - 郵差帽：轉交中的推車
  - 手上的錢袋：拿著錢、超過天數沒繳
- 名牌：角色腳下一個白色小膠囊。

### 3.5 HUD 與泡泡

- **HUD 膠囊**：
  - 外觀：底色 `#FFFDF7`，全圓角，陰影 `0 2px 0 rgba(77,66,57,.10), 0 6px 18px rgba(77,66,57,.10)`。
  - 左邊一個 31px 的圓形圖示，數字用 Fredoka 21px，標籤 12px。
- **小膠囊**：高 30px，用來放第二排的預收、待發、基金。
- **世界裡的泡泡**：白色圓角，下面有小尾巴，帶 drop shadow；內容是圖示加金額。
- **底部圓形按鈕**：白色，外圈奶油色 `#F1E4C9`，圖示是深色線條 icon，下面有文字標籤（一定要有字）。
- **主堡卡片／抽屜**：圓角 28px，地圖其他地方變暗，被點的東西用 radial-gradient 留亮。

### 3.6 動畫

會動的東西：
- ❗ 上下跳
- 旗子飄
- 跳舞的奇異鳥
- 沙漏條的斜紋流動
- 河面波紋
- 冒煙
- 新收款的 +$ 浮起
- （開發時）推車出發、進門、掉頭，箱子堆疊

全部都要有 `@media (prefers-reduced-motion: reduce)` 版本，關掉動畫。動畫只是加分，資訊不能只靠動畫傳達。

## 4. 版面

### 4.1 電腦（≥ 1024px）：橫式地圖

- **場景**：1280×800。台南在左下，高雄主堡在右上，河斜斜地把兩邊隔開。
- **HUD**：
  - 左上：教室徽章，下面標月份
  - 第一排：公司的錢、主堡財庫、還在路上、建城貸款進度條
  - 第二排：預收、待發、基金
  - 右上：帳本、通知、說明
- **左側「代收人背包」卡**：每個代收人一格。底部有波浪花紋。
- **下方四顆圓形按鈕**：帳本模式、我的背包、送回主堡、記一筆。
- **點開主堡**：左側出現卡片，主堡留亮。卡片內容依序是：
  1. 財庫
  2. 這些錢是誰的
  3. 建城貸款
  4. 等你確認
  5. 本月進出

### 4.2 手機（< 1024px）：直式地圖

- **場景**：設計座標 520×1125，畫面上縮成 0.75 倍（390×844）。泡泡和名牌另外放大 1.25 倍，所以字不會小於 11px。
- **排法**：主堡在上，河橫在中間，台南丁丁家在下。路從主堡門口蜿蜒往下，過橋到台南。
- **HUD**：
  - 第一排：徽章、公司的錢、通知
  - 第二排：財庫、路上、回本 %
  - 預收、待發、基金收進主堡抽屜，不放在 HUD
- **下方**：「代收人背包」一排可以左右滑的卡片，再下面是四顆圓形按鈕。
- **點東西就從下方拉出抽屜**，被點的東西留在上方亮著：
  - **主堡抽屜**：老闆第一眼看到的是「等你確認」，往下滑依序是財庫、這些錢是誰的、建城貸款。
  - **送回主堡抽屜**：
    - 金額預設帶入背包全部
    - 選現金或轉帳，填末五碼、日期，備註選填
    - 按「出發！」送出
- 最窄要照顧到 360px 寬，地圖等比縮。
- 平板直向（768～1023px）用手機版，地圖置中放大。

### 4.3 手機要不要縮放（已評估）

| 做法 | 結果 |
|---|---|
| A 直接縮小電腦版 | ✗ 1280 寬縮到 390，字剩約 4px、按鈕約 20px |
| B 像遊戲一樣拖曳加縮放 | △ 看得清楚，但一次只看到約 1/3 張地圖。找人要拖，容易誤觸，還得加小地圖 |
| C 直式重新排版 | ✓ 一個畫面放下全部，不用縮放 |

**結論：第一版不做自由縮放。**
- 「點了才放大」取代縮放：點一個東西，就拉出抽屜，鏡頭自動對準它。
- 代收人超過 6 位，或分部超過 3 個，地圖會擠。這時先把手上 $0 的人收進背包列，真的放不下再加縮放。

## 5. 不能破的規則

1. **數字以 HUD、卡片、抽屜為準**。畫面上的東西都是示意：箱子數四捨五入，推車位置是狀態，不是真的距離。
2. **每個遊戲畫面都有「帳本模式」**，一鍵切回明細表。對帳、找某一筆，都在帳本模式做。
   **反過來也一樣：帳本看得到的，遊戲模式也都要找得到**（2026-10-28 使用者要求）。對應如下：
   - 主堡：主堡的進出，包括老闆收的、入庫的繳回、支出、補錢、期初
   - 人：背包裡的收款，和送回紀錄（含退回、撤回）
   - 建築：台南丁丁家、高雄教室的場地規則和場地費
3. **地區不畫成金庫**。課卡兩地共用，錢只有主堡一個庫（`finance-plan.md` 的原則）。
4. **權限跟著資料走**。只有營收負責人看得到「收到了」「金額不對」。其他人看到同一張卡，但沒有按鈕。
5. 可用性的最低標準：
   - 點擊範圍至少 44px
   - 地圖上的字至少 11px
   - 同時最多 5 個泡泡，其餘收成小圓點
   - 圖示按鈕一定有 `aria-label`
   - 狀態不能只靠顏色表示，要有字，例如「32 天沒繳」「等確認」
6. **只借遊戲的手法**，不用其他遊戲的角色、圖像、Logo 或名稱。
7. **跟 [`design-system.md`](design-system.md) 的關係**：
   - 遊戲畫面自成一套，用暖色和 Fredoka。
   - 主要按鈕和綠色系沿用 primary。
   - 帳本模式、表單細節、設定頁用一般的設計系統元件，不要遊戲化。

> **可以操作的示意版（2026-10-28）**：`/finance/town`（`src/features/finance/town/`），還沒接資料庫，資料只在記憶體裡，重新整理就還原。

  - 投影函式 `P(gx, gy, z)`，物件依 `gx + gy` 排深度（可以參考 `gen_game.py` 的 `box`、`crate`、`kiwi`）。

- **人變多時**：手上 $0 的人不畫角色；代收人超過 6 位，地圖上只畫前 5 位，其他人在背包列。

## 8. 還沒決定

- **回本 % 的公式**：暫定「水庫基金 ÷ 欠老闆的」。另一個選項是「公司淨值從最低點回升了多少」。
- **箱子單位**：固定 $1,000 一箱，還是依金額自動調整（錢很多時改成大箱）。
- **推車沙漏的期限**是幾天（暫定 3 天），超過要不要再推播老闆一次。
- **同時有好幾台推車**到門口怎麼排：排隊，還是疊成一台加數字。
