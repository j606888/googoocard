## 1. 教室的真實情況（前提）

以 Bailamore 為準，但規則都要做成資料，不寫死。

- **老闆是 Sean**，人在高雄，保管公司的錢（大水庫）。他跟其他老師一樣，**教課才有收入**；大水庫裡的錢不是他的薪水。他也是 `Teacher` 裡的 Sean，大部分的課是他教的。
- 課卡高雄、台南**共用**。
- 台南所有課（含週日）的課卡錢由**丁丁代收**，之後繳回大水庫。以前學生是轉給各老師的 LINE／銀行。
- 台南教室是丁丁家。Sean 付丁丁**場地費每天 $500**、每位助教 **$250**。
- 高雄在 24steps 上課，場租是**一次預付 10 堂**（例：$4,050 ＝ 每堂 $405），臨時換教室時價格會變。
- Party 酒水由 Sean 直接付，或先墊再請款。
- **教師費現在是每堂當天發現金，啟用水庫後改成月結。**
- 丁丁的鐘點／分潤，月結時可以直接從他手上應繳回的代收款扣掉。

### 1.1 Sean 現在的 Excel（Google Sheet）

兩個分頁：「收支明細」和「大水庫結餘」。收支明細每天一個區塊，其實是兩本帳：

- **左邊：當天的現金收支**。收入（課卡逐人、單堂、體驗課）− 支出（場地費、飲料費、教師費、廣告費、24steps 場租）＝ 當天的「大水庫結餘」。
- **右邊：每堂課的分帳**（「課程計算」）：

  | 欄位 | 算法 |
  |---|---|
  | 點名收入 | 這堂點名認列的收入（不是當天收到的現金） |
  | 場租 | 台南：$500 ÷ 當天堂數（兩堂各 $250）；高雄：預付場租的每堂價（$405） |
  | 10% 進大水庫 | （點名收入 − 場租）× 10% |
  | 教師分潤計算 | （點名收入 − 場租 − 10%）÷ 老師人數 |
  | 取整數 | 每位老師實拿；左邊的「教師費」＝ 取整數 × 老師人數 |

  實例：SALSA 體驗 2000 − 250 ＝ 1750，10% ＝ 175，÷2 ＝ 787.5 → 780，教師費 1560。

這跟我們的模型對得上：左邊＝代收／大水庫（第一步），右邊＝每堂分帳（第二步）。

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| **代收** | 學生付給某位成員、還沒繳回大水庫的課卡錢。代收人就是課卡頁按「確認收款」時選的人（`StudentCard.paidByUserId`），**教室裡誰都可以**。 |
| **大水庫** | 公司的錢，Sean 保管。只看一個總數，不分銀行和現金。 |
| **繳回** | 代收人把錢交進大水庫，要**營收負責人確認收到**才算數。 |
| **大水庫支出** | 從大水庫付出去的錢：場地費、場租、助教費、教師費／發薪、廣告費、飲料費、Party／公共、其他。 |
| **預收** | 學生已經付錢、還沒上的堂數的價值。 |
| **預付場租**（先不做） | 已經付給場地、還沒用掉的場租（例：24steps 10 堂付了 $4,050、用了 3 堂 → 還有 $2,835）。是公司的資產，每上一堂就攤掉一堂。 |
| **待發** | 已經上過課、算好了，但還沒付出去的教師費和場地費（第二步）。月結之後，月中的分潤都在這裡。 |
| **水庫基金** | 每堂課扣完場地費後抽的 10%，**公司真正的錢**。Party 支出從這裡出，Party 賺的錢也回到這裡（第二步）。 |
| **欠老闆的** | Sean 前期投入，以及之後自己掏錢補進大水庫的部分，一律算「借給公司」。**只記帳、不規劃還款**，讓大家看到回本進度。 |
| **營收負責人** | 系統裡代表 Sean 的那位成員（水庫設定裡選）。只有他能確認繳回、記大水庫支出，推播也發給他。 |
| **啟用日** | 水庫開始記帳的那天（建城當天，不等月初）。這天之後的課卡收款、支出、分帳、薪資都走系統；之前的留在 Excel。 |

### 公司的錢怎麼看

```
公司的錢總共 ＝ 大水庫 ＋ 還在代收人手上 ＋ 轉交中

公司的錢總共 ＝ 預收 ＋ 待發 ＋ 水庫基金 − 預付場租   （第二步才拆得出來）

公司淨值     ＝ 公司的錢總共 ＋ 預付場租 − 預收 − 待發 − 欠老闆的   （負的＝還沒回本）
```

## 3. 原則

- **全公開**（第一版）：教室每個人都看得到總覽、大水庫收支、每位代收人的明細。只有「確認收到」和「記大水庫支出」限營收負責人。
- **核心資料只讀不抄**：課卡收款、點名、課程老師都直接讀核心的表。水庫只存自己的東西，不存核心資料的副本。
- **跟著課程走，不跟分部走**：課卡共用，所以不用把收入分給台南或高雄。分部只當預設值（例如場地費）和報表標籤。
- **改動留紀錄**：手記的帳可以改，但要寫原因，修改紀錄大家都看得到。不真的刪除。
- **系統是正本，Google Sheet 是副本**（§9）。

## 4. 啟用與建城（第一次使用）

### 4.1 從 Excel 轉過來：不搬歷史，只搬啟用日的狀態

Excel 留著當**舊帳**（唯讀，不再更新）。歷史不逐筆匯入：日期、格式、教師費和課程都對不準，而且舊帳之後不會再算。

啟用日要填的數字：

| 要填的 | 從哪裡來 |
|---|---|
| 大水庫現在有多少（現金＋銀行一個數） | Excel「大水庫結餘」分頁的累計數，再跟 Sean 的存摺和現金對過 |
| 欠老闆的 | 結餘累計是負的部分＝ Sean 自己的錢（已確認） |
| 誰手上還有沒交的錢（期初代收） | 問丁丁和各老師，每人一個數 |
| 待發 | 啟用前教師費都當天發完，應該是 0 |
| 預收 | **不用填**，課卡本來就在 Googoocard，系統自己算 |

- **啟用日之前付款的課卡不算代收**。舊資料一律 `isPaid = true`、`paidByUserId = null`，不能讓它們全部變成某人的代收。
- 啟用日之後付款、卻沒記收款人的卡，進「不知道誰收的」，提醒大家認領，不默默算給誰。
- 啟用日在**第一筆繳回確認之前**可以改（＝重新開帳）；之後就鎖住。期初數字可以改，要寫原因、留紀錄。
- 啟用日當月的第一次月結，只算啟用日～月底。啟用日之前那幾天的教師費已經在 Excel 當天發掉了。

### 4.2 並行期

啟用後一到兩週，Sean 照樣記 Excel，系統同時跑，每天對「教師費」和「大水庫結餘」。系統提供一個**對帳**小工具：輸入 Excel 的數字，直接顯示有沒有差、差在哪幾筆。連續對上之後才停用 Excel。

### 4.3 建城流程

空白畫面是一塊空地、施工中的主堡、任務清單（畫面見 `finance-game-style.md`）。每答一題，小鎮就長出一塊：

1. **誰保管公司的錢？** 選一位成員當營收負責人 → 戴皇冠的奇異鳥走進主堡。
2. **啟用日**：預設今天 → 主堡插上旗子。
3. **大水庫現在有多少錢？** → 箱子堆進倉庫。
4. **你自己放了多少錢進來？**（選填，可以略過）→ 建城貸款的進度條出現。略過就不顯示建城貸款和回本進度，之後在水庫設定補。
5. **現在誰手上還有沒交的錢？** → 那些人背上背包。

答完先**試玩一次**：一台練習推車開到門口，請 Sean 按「收到了」，看入庫動畫。練習推車不寫進資料庫。這一步在他手機上做，順便開推播。

- 開模組要 owner／admin（丁丁），建城要營收負責人（Sean）。順序：丁丁開模組、選 Sean → Sean 登入建城。
- 建城前其他人打開水庫：「主堡施工中，等 Sean 完成建城」，不能操作。
- 建議第一次坐在旁邊，用電腦建城；最後在 Sean 的手機上試玩、開推播。

### 4.4 新手任務（依角色，全部完成就收掉）

| 角色 | 任務 |
|---|---|
| owner（丁丁） | 開啟水庫模組 → 選營收負責人 → 通知大家把網站加入主畫面 |
| 營收負責人（Sean） | 建城 → 加入主畫面、開推播 → 試玩推車 → 連上 Google Sheet → 記第一筆支出 → 第一次確認真的繳回 |
| 代收人 | 加入主畫面、開推播 → 看一次我的背包 → 第一次送回主堡 |
| 老師 | 確認自己對應哪位 `Teacher` → 看第一堂課的分潤 |

- 一個人可以同時有好幾個角色，任務清單合併、去重。
- 任務是「真的發生了」才打勾（例：第一次真的繳回被確認），不是看完說明就打勾。
- 「開推播」先偵測是不是從主畫面開的（`display-mode: standalone`）。不是的話，秀 iPhone／Android 加入主畫面的圖解，因為 iPhone 只有從主畫面打開才能開網頁推播。

## 5. 第一步：代收＋繳回＋大水庫收支

這一步完全不用碰分帳規則。

### 5.1 畫面

| 畫面 | 誰能操作 | 內容 |
|---|---|---|
| 總覽 | 大家看 | 公司的錢總共多少（大水庫＋還在路上的）；拆成預收和「其他」（第二步再拆成待發和水庫基金）；欠老闆的、淨值；每位代收人的收、繳、手上餘額，超過 N 天沒繳標紅；等確認的繳回 |
| 我的代收 | 本人（大家可以看任何人的） | 像存摺一樣逐筆列課卡收款和繳回，每筆後面有手上餘額；連到還沒付款的課卡 |
| 繳回 | 代收人送出，營收負責人確認 | 金額（預設帶入手上全部）、轉帳或現金、末五碼、日期、備註；還沒確認前可以撤回或改；營收負責人按「收到了」或「金額不對」（要寫原因，退回去改） |
| 大水庫收支 | 大家看，營收負責人記 | 大水庫的存摺：進來的自動帶入（營收負責人自己收的課卡、確認過的繳回），出去的手記；期初餘額；欠老闆的增加或減少 |

支出分類照 Sean 的 Excel：場地費、場租、教師費（月結後是「發薪」）、助教費、廣告費、飲料費、Party／公共、其他。

### 5.2 推播（網頁推播）

- 有人送出繳回 → 推播給營收負責人。
- 繳回被確認或退回 → 推播給送出的人。
- 沿用現有的 `WebPushSubscription`，要加一種 `NotificationPreference`。不走 Expo／App。

### 5.3 資料（草稿，開發前再定）

- `FinanceRemittance`：從誰（userId）、金額、方式（cash／transfer）、末五碼、日期、備註、狀態（pending／confirmed／rejected）、確認或退回的人和時間、退回原因。
- `FinanceEntry`：大水庫的手記帳。日期、分類、金額（正負）、付給誰（userId 或文字）、說明、記錄人；外加修改歷程。
- `FinanceSetting`（或掛在 `ClassroomModule` 的設定）：營收負責人 userId、啟用日、期初餘額、幾天沒繳標紅、Google Sheet id。
- 期初代收：每人一筆，算在他背包的起點。
- 欠老闆的：做成 `FinanceEntry` 的一種分類（老闆投入），或另開一張表。⚠️ 待定。
- 預付場租：**先不做**（2026-10-28），建城不問。之後跟第二步的場地設定一起定：一筆「付了多少、幾堂」的紀錄，每上一堂該場地的課就攤掉一堂。
- 新手任務進度：每人每個任務完成時間（任務本身寫在程式裡）。
- 課卡收款**不用新表**：讀 `StudentCard`（`paidByUserId`、`paidAt`、`finalPrice`、`paymentMethod`、`paymentReference`，只算 `origin = PURCHASE`、`paidAt ≥ 啟用日`）。

## 6. 第二步：每堂課怎麼分帳

改成月結以後，**第一次月結之前**要做好（不用在啟用日前）。

### 6.1 規則

一堂課（＝一個點過名的 `LessonPeriod`）：

```
收入   ＝ Σ 每位出席者那張卡的每堂價（finalPrice ÷ totalSessions），沿用 src/lib/income.ts 的 periodRevenue
− 場地費（預設看分部或課程，每堂可以改）
− 水庫基金（扣完場地費後的 10%，規則可以關掉）
＝ 剩下的，照分法分給這堂的老師，每人再取整數
```

| | 高雄（24steps） | 台南週日 | 台南週二（丁丁的課） |
|---|---|---|---|
| 誰教 | Sean＋另一位老師 | Sean 或他請的老師 | 丁丁 |
| 場地費 | 預付場租的每堂價（$405，可以改） | 當天 $500 **平均攤**到當天每堂 | 不扣 |
| 10% | 抽 | 抽 | **先假設不抽** |
| 剩下的 | 平分 | 平分給授課老師 | 丁丁 |

- **取整數**：Sean 在 Excel 裡是憑感覺取整數，大多是捨去到十位（945 → 940、787.5 → 780、177.75 → 170），偶爾捨到百位（1617.75 → 1600）。系統**預設捨去到十位**，月結前每堂的實拿金額可以手動改（照「改動留紀錄」，要寫原因）。捨掉的零頭**歸 Sean**（記成他的分潤，不進水庫基金）。
- **台南 $500 平均攤**：當天點過名的台南課堂數 N，每堂 $500 ÷ N。只有一堂就全扣在那堂。
- **高雄預付場租**：每上一堂高雄的課，從預付場租攤掉一堂的價錢。預付用完還在上課 → 提醒 Sean 該續付。
- **預設規則＋手動覆寫**：一般課套規則自動算。臨時活動、體驗課等，可以**手動填收入，以及誰分多少**。
- **助教費不算在課程裡**：Sean 從大水庫出，跟學生多少無關。之後可以照台南週日自動產生「待發」。
- 規則有版本，已經結算的月份不會因為改規則而變動。

這些資料帶出的問題：

1. **分部還沒設定**：教室沒有 `Location`，高雄只靠課名的「[KH]」辨認。場地費預設要靠分部，所以第二步之前要先在 `/locations` 建好台南、高雄，並掛到每堂課上。
2. ~~台南 $500 怎麼攤~~ → 平均攤（§6.1）。
3. **雙師沒有記在課程上**：Excel 每堂都是 ÷2，但 9～10 月的課都只掛 Sean 一位（3 月、6 月的才是 Sean＋Kathy）。分帳讀的是 `Lesson.teachers`，所以老師要掛正確，或在結算時可以改。
4. **老師對不上人**：這間教室的 `Teacher` 只有 Sean、Kathy、Nini。Sean ＝ 老闆；丁丁還沒有 `Teacher`。要用 `Teacher.userId` 連到成員，薪資和代收扣抵才接得起來。
5. **單堂實收不一樣**：「進階單堂」定價 $350，但點名認列有 $167、$333（`finalPrice` 被改過）。收入公式照 `finalPrice` 算，所以沒問題，只是要知道會這樣。
6. **有沒卡就上課的**（9/20 兩位）：欠卡要怎麼算進收入，見 §8。
7. **9～10 月沒有看到台南週二的課**：是還沒開，還是記在別的教室（例如「丁丁教室」）？

## 9. Google Sheet 同步（備份，單向）

讓 Sean 有一份熟悉、在他自己 Google 帳號裡的副本。

- **單向**：系統 → Sheet。Sheet 是唯讀副本，在 Sheet 上改的東西下次同步會被蓋掉；要改帳回系統改。
- **用推的**：系統主動寫進 Google，不用 `IMPORTDATA` 從我們的網址拉。這樣就算系統掛了，資料還在他的 Google 裡。
- **做法**：Google Cloud 專案 `googoocard` 開一個服務帳號；Sean 把他的 Sheet 分享給服務帳號 email（可編輯），在建城任務裡貼上 Sheet 網址。每次記帳／確認繳回就寫一次，每晚再全量覆寫一次，避免漏寫。
- **版面照他現在的 Excel**：「收支明細」（每天一個區塊：左邊收入、支出、當天結餘；右邊課程計算）＋「大水庫結餘」累計。另加一個「代收人」分頁。
- **限制**：每晚全量覆寫需要排程，專案目前還沒有 `vercel.ts` cron，要跟續卡提醒的 cron 一起處理。同步失敗要在水庫畫面上看得到（「Sheet 上次同步：…」）。
