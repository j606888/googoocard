## 整體方向

- **開帳要像 onboarding**：開財務後強制走完開帳流程才進得了總覽／報表／結算（每步可跳過）。（#5）
- **步驟更明確、有趣**：整個流程要走 15–20 分鐘，每一步都要讓人一眼知道「現在在做什麼、為什麼、做完會怎樣」——
  每步配插圖／圖例、一句白話目的、具體範例（用這間教室的真實名字和數字），而不是一段說明文字。（#14）
- **少字**：「要注意」每步只留 1–2 條最重要的，其餘收進 ⓘ。（#10b，要一起挑）
- **一層進度就好**：開帳裡不要再藏小步驟。（#12e）

## 查證結果（2026-11-09）

**上線日 vs 轉換日 → 建議合併（85，下一輪，跟 12e 一起）**
- 上線日（financeEnabledAt）：舊卡到期＝上線日＋6 個月（service/finance/setup.ts:31,53-56）、v1 時段／過期／收款人整理／之前的次數包的範圍、開帳建議日、開帳前帳本的後備轉換日（ledger/load.ts:55-57、guard.ts:19）
- 轉換日（financeConversionDate）：哪些卡／時段／支出過帳、期初分錄日、次數包從哪天扣
- 沒有必須不同的情況；不同時反而會錯：轉換日早於上線日前一天 →「之前的次數包」被當成轉換日後的現金支出，跟期初預付重複
- 做法：開財務不問日期（financeEnabledAt = now）；開帳只問轉換日；開帳時舊卡到期改轉換日＋6 個月；v1 查詢改讀 guard.ts 的轉換日
- 連帶：#4 的日期快捷鍵搬到開帳的轉換日

**「帳本有記不進去的紀錄 1 筆」→ 開帳前就跑 sync 造成的假警報（88，下一輪）**
- syncLedger 不檢查開帳沒，開帳前用上線日當轉換日跑（reports.ts:46）；資金帳戶只幫有負責分部的保管人建（ledger/setup.ts:52-67）→ 剛開財務還沒設負責人，上線日後付款的那張卡 NO_MONEY_ACCOUNT
- 修法：financeOpenedAt 為 null 時 syncLedger 直接 return；總覽的 ledgerErrors 只在開帳後顯示（開帳 preview 本來就會擋）

## #9 場地與次數包——已定案（2026-11-10）
- 按次付的金額設在場地上（所有課共用），個別課可在分帳規則用固定金額覆寫
- 場地歸屬分部：場地費與次數包一律從該分部負責人的錢付，拿掉「誰付的」
- 場地卡片列出收費方式（每次 $X／儲值包 N 次 $Y、每次 $Z、還剩幾次）；開帳時補登「手上這包還剩幾次」，開帳後才有「買一包」
- 沒用過的場地可刪除；次數包看得到、可作廢
- 狀態：🤖 subagent 進行中（含 migration finance_venue_billing）
