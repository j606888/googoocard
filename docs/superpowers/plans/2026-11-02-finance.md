# 財務（分部、分帳、保管中、月結）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bailamore 可以在網頁上看到每堂課自動分帳、每個保管人的「保管中」、每月結算鎖定與轉帳，並支援綁課卡／贈送卡／6 個月到期。

**Architecture:** 純計算放 `src/domains/finance/`（分帳、收入、保管中、月份歸屬，全部可單元測試，數字以 JS number 保留小數）；讀寫資料放 `src/service/finance/`；API 在 `src/app/api/finance/**`；畫面在 `src/app/(main)/finance/**` 與 `src/features/finance/**`。**能算的不存**：每堂分帳、保管中、結算單都即時算；只存規則、支出、次數包、轉帳、退費、缺席扣格、月結快照。整個功能由 `Classroom.financeEnabledAt` 開關，沒開的教室行為完全不變。

**Tech Stack:** Next.js 15 App Router、Prisma 6 + Postgres、zod、RTK Query、Tailwind v4、Vitest（整合測試跑本機 docker 的 `googoocard_test`）。

**Spec:** `docs/superpowers/specs/2026-11-02-finance-design.md`（下稱「spec」，§ 指它的章節）。實作前兩份都要讀。

## Global Constraints

- 只用 `npm run db:migrate` 建 migration；**絕不** `prisma db push` / `migrate reset`（`CLAUDE.md`）。
- 財務只對 `Classroom.financeEnabledAt != null` 的教室生效；其他教室：卡不到期、收款人可選任何成員、沒有綁課卡／贈送卡、不能用財務 API（回 404 `FINANCE_DISABLED`）。
- 只做網頁版，`mobile/` 不動。
- 金額：人輸入的（支出、次數包、轉帳、退費、期初）是整數元 `Int`；計算結果保留小數，畫面四捨五入到元；**只在月結發錢時**把每人月合計取整到 `Classroom.financeRoundTo`（預設 1），零頭進付款人負責分部的公積金（§7.5）。
- 每格價值 = `finalPrice / totalSessions`；收入只算**已付款**的（§4.1）。
- 人拿到的永遠 ≥ 0；不夠的差額由這堂課的基金吸收（§4.2）。
- 月份一律台北時間 `YYYY-MM`；日期用台北當天。
- 每個 API 走 `apiRoute`（`src/lib/apiRoute.ts`），用 `classroomId` scope；寫入類要 `assertFinance`（Task 2）。回應不得 spread DB row（`docs/roadmap.md` IDOR 規則）。
- UI：沿用共用元件（`Button`、`Field`、`EmptyState`、`Skeleton`、`StatusTag`、`Drawer`），遵守 `docs/ui-responsive.md`；說明收進 ⓘ，不放統計列。文案繁體中文。
- 人名、舞種、分部都是資料，程式裡不准寫死（不准出現 "Sean"、"台南"）。

## Review Focus

1. **同一堂課重複點名／改點名**：老師按兩次「更新點名」、或先取消再勾回一位綁課卡學生，缺席扣格不能重複、課卡格數要對（Task 11 測試 `absence is idempotent across repeated updates`）。
2. **月結鎖住後才收到錢或改點名**：差額只出現一次，在最早還沒鎖的月份；再下一個月鎖住後不會再出現一次（Task 13 測試 `delta appears once and is absorbed by the next lock`）。
3. **一堂課錢在兩個人手上**：保管中「欠對方」兩邊要對得上，總和等於現金（Task 12 用 §14 整份模擬測試，並 assert 兩人的 peer 互為相反數）。
4. **沒開財務的教室**：賣卡、確認收款、點名、作廢都跟今天一模一樣（Task 9、10、11 各有一個 `finance disabled` 測試）。
5. **次數包用完還沒記新的、或同場地有兩包不同價**：先買先用，用完照上一包單價、剩餘變負（Task 5 測試 `pack FIFO and overdraw`）。

### Task 3: 分帳計算（純函式）

**Files:**
- Create: `src/domains/finance/types.ts`、`src/domains/finance/split.ts`
- Test: `src/domains/finance/split.test.ts`

**Interfaces:**
- Produces（`types.ts`）：
```ts
export type Payee =
  | { type: "teacher"; teacherId: number }
  | { type: "fund"; locationId: number }
  | { type: "venue"; venueId: number; packId?: number };
export type SplitLine =
  | { kind: "fixed"; amount: number; to: Payee }
  | { kind: "percent"; pct: number; base: "income" | "remaining"; to: Payee }
  | { kind: "venuePack"; venueId: number };          // 存在規則裡；計算前由 Task 5 換成 fixed + packId
export type RestTarget =
  | { type: "teachers"; shares: { teacherId: number; weight: number }[] }
  | { type: "fund"; locationId: number };
export type SplitRule = { lines: SplitLine[]; rest: RestTarget; fundLocationId: number };
export type ResolvedLine = Exclude<SplitLine, { kind: "venuePack" }>;
export type Allocation = { payee: Payee; amount: number; source: "line" | "rest" | "deficit" };
```
  - `splitRuleSchema`（zod，驗 `SplitRule`；`pct` 0–100、`amount` ≥ 0、`weight` > 0、`shares` 至少一位）
  - `computeSplit(income: number, lines: ResolvedLine[], rest: RestTarget, fundLocationId: number): Allocation[]`
    - 由上往下；`percent/income` = pct% × income；`percent/remaining` = pct% × max(0, 前面扣完剩下的)；`fixed` 全額。
    - R = income − Σ lines。R ≥ 0：teachers 依 weight 分、或全給 rest fund。R < 0：每位 rest 老師一筆 amount 0（source `rest`），再一筆 `{fund: rest 是 fund 時用它，否則 fundLocationId, amount: R, source: "deficit"}`。
    - 回傳的 Σ amount 永遠 = income（浮點誤差 < 0.005）。

- [ ] **Step 1: 寫失敗測試**（數字全部來自 spec §13，`toBeCloseTo(x, 2)`）：
  - `tainan rule (case 1)`：income 666.67，lines `[丁丁 percent/income 33.333…, Charlene 33.333…, fixed 300 venue丁丁家]`，rest fund 台南 → 222.22／222.22／300／fund −77.78。用 `pct: 100/3`。

  - `zero income`：income 0 台南規則 → 0／0／300／−300。
